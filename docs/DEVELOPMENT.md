# Open Physics 개발 현황 및 기본 아키텍처

> 이 문서는 현재까지 구현한 물리 엔진과 여섯 물리 영역의 안내형 실험실·빈 실험실 상태를 기록하는 개발 기준 문서다.

새 물리 영역을 역학과 같은 완성도로 확장할 때는 [물리 실험실 구현 가이드라인](./LAB_IMPLEMENTATION_GUIDELINES.md)을 먼저 따른다.

## 1. 프로젝트 목표

Open Physics는 물리학을 시각적으로 실험할 수 있는 인터랙티브 물리 시뮬레이션 프로젝트다. 현재 제품은 웹 2D이며, 3D 모바일 앱으로 전환하고 있다([ADR 0001](./adr/0001-3d-app-stack.md)).

핵심 목표는 실제 세계의 모든 물리 현상을 정밀하게 재현하는 것이 아니다. 사용자가 물체와 환경을 직접 조작하면서 **물리학의 공식과 관계를 시각적으로 이해하고 실험할 수 있는 공간**을 만드는 것이다.

주요 원칙:

- 백엔드 없이 프론트엔드에서 시뮬레이션을 실행한다.
- 현재 웹 제품의 기본 공간은 2D이며 유지보수만 한다. 새 기능은 3D 앱(Three.js + Rapier + Capacitor)에서 만든다.
- 물리 엔진은 실제 물리의 완전한 재현보다 교육적이고 가정된 물리 모델을 우선한다.
- 공식과 물리 법칙을 명시적인 코드 단위로 관리한다.
- 같은 물리 공간 안에서 객체를 자유롭게 추가하고 이동할 수 있어야 한다.
- 학습 단계에 따라 사용할 물리 법칙을 제한하거나 활성화할 수 있어야 한다.
- 설명 UI와 물리 엔진을 분리한다.

## 2. 콘텐츠 영역

전체 콘텐츠의 큰 분류는 다음과 같다.

| 영역 | 안내형 실험 | 빈 실험실 | 주요 관찰 표현 |
|---|---:|---:|---|
| 역학 | 10 | 1 | 운동, 힘·가속도 벡터, 연결 장치, 궤도 |
| 전자기학 | 9 | 1 | 전하와 전기장, 충전·방전 회로, 자기장·유도, 실제 부하가 연결된 전자석·전동기·발전기·변압기 |
| 파동 | 7 | 1 | 파형·파면, 중첩, 정상파, 소리 |
| 빛 | 8 | 1 | 광선, 상, 스펙트럼, 간섭 무늬 |
| 열 | 7 | 1 | 입자 운동, 열 이동, 상태 변화, P–V 경로 |
| 현대물리 | 8 | 1 | 시공간 비교, 준위, 확률 분포, 검출 통계 |

현재 총 49개 안내형 실험과 영역별 빈 실험실 6개가 같은 상위 영역 탐색과 같은 `실험 선택` 제품 흐름에 연결되어 있다. 모든 안내 실험은 탐구 질문, 세 단계 조작, 관찰 포인트, 관련 법칙, 단위가 있는 그래프를 제공한다.

영역 전환은 `src/app/main.ts`가 URL의 `subject` 값을 읽고 해당 `SubjectExperience`만 동적으로 불러오는 방식이다. 기존 역학 UI와 긴 실행 상태는 `src/app/mechanics-main.ts`에 격리되어 있으며, 다른 다섯 영역의 콘텐츠·상태·Canvas 상호작용·렌더링은 `src/app/subjects/<영역>/` 내부에 숨긴다. 공통 셸은 영역 내부 장치 타입이나 방정식 매개변수를 알지 않는다.

여섯 영역 모두 `subject`만 있는 URL을 실험 선택 화면으로, `lab=<id>`가 추가된 URL을 전용 실험 화면으로 사용한다. 역학은 `?lab=<id>`, 나머지는 `?subject=<영역>&lab=<id>` 형태다. 전용 화면의 좌측 패널은 조건·물체 설정·빈 실험실 도구, 중앙은 Canvas, 우측은 설명·관찰값·그래프를 맡는다. `SubjectRouteSession`이 URL 해석과 생성, `pushState`, `popstate`, 직접 진입 복구를 담당하므로 각 물리 모델은 브라우저 history를 알지 않는다.

병렬 개발용 `.worktrees/`는 Git과 Vitest 탐색에서 제외한다. 따라서 루트 `npm test -- --run` 결과에는 현재 통합 브랜치의 테스트만 한 번씩 포함된다.

교육과정은 제품의 절대적인 제약이 아니라 콘텐츠를 단계적으로 제공하기 위한 가이드라인으로 사용한다.

## 3. 물리 모델의 기본 철학

Open Physics의 물리 엔진은 '실제 세계와 똑같은 물리엔진'을 목표로 하지 않는다.

예를 들어 중력은 일반적인 시뮬레이션 상황에서 다음과 같은 공식으로 표현할 수 있다.

```text
F = mg
```

객체에 작용하는 힘을 계산하고,

```text
a = F / m
```

을 통해 가속도를 얻은 뒤 solver를 통해 속도와 위치를 갱신한다.

이 구조를 유지하면서 사용자가 학습 단계에 따라 활성화할 물리 법칙을 선택할 수 있도록 한다.

## 4. 엔진 구조

현재 물리 코어는 다음 구조를 가진다.

```text
PhysicsSimulation
│
├── Bodies
│   ├── position
│   ├── velocity
│   ├── acceleration
│   ├── mass
│   ├── radius
│   ├── restitution
│   ├── staticFriction
│   ├── kineticFriction
│   └── fixed
│
├── Laws
│
├── Fields
│
├── Constraints
│
├── Collision
│
└── Solver
```

### 4.1 Body

물리 공간 안에서 움직이는 객체다.

기본 상태에는 위치, 속도, 가속도, 질량이 포함된다.

시각화 객체는 물리 객체와 분리한다. 따라서 Canvas 렌더링을 변경하더라도 물리 코어 자체는 변경하지 않는 것을 원칙으로 한다.

### 4.2 Force Law

특정 물리 법칙을 힘 계산으로 표현한다.

예:

```text
중력
스프링
마찰
전기력
```

법칙은 가능한 한 공식 단위로 독립적인 테스트를 작성한다.

### 4.3 Spatial Field

객체에 직접 붙는 것이 아니라 공간에 존재하는 물리적 환경이다.

현재 구현된 대표적인 Field:

```text
UniformGravityField
PointGravityField
UniformElectricField
UniformMagneticField
```

예:

```text
Uniform gravity
F = mg

Electric field
F = qE

Magnetic field
F = q(v × B)
```

이 구조를 이용하면 사용자가 특정 공간에 전기장이나 중력장을 배치하고 객체를 그 안으로 가져가는 방식의 인터랙션을 구현할 수 있다.

### 4.4 Constraint

객체 사이의 관계를 유지하는 제약조건이다.

코어는 두 물체 사이의 거리 제약을 지원한다. Playground에는 이 원리를 쉽게 관찰할 수 있도록 다음 교육용 모델을 제공한다.

- 줄과 막대: 고정점과 추 사이 거리 `L`을 유지한다.
- 진자: 비선형 진자 방정식 `θ'' = -(g/L)sinθ - bθ'`을 사용한다.
- 도르래: 짐을 받치는 줄의 수 `n = 1, 2, 4`에 따라 이상적인 필요 힘 `F = mg/n`과 거리 교환 `d당김 = nd상승`을 계산한다.

현재 교육용 도르래는 마찰과 줄·도르래 질량을 무시한 이상 모델이다. 필요한 힘의 차이를 포인터 조작으로도 느낄 수 있도록 같은 드래그에서 손잡이가 따라오는 비율을 1줄 25%, 2줄 50%, 4줄 100%로 둔다. 이 비율은 교육용 저항감이며, 모델에 기록하는 실제 줄 당김 거리는 이상 도르래 식 `n × d상승`으로 별도 환산한다. 한 번의 드래그 길이에 고정 상수를 두지 않고 Canvas 바닥과 장치의 안전 상승 높이만 제한하며, 손잡이를 놓으면 당긴 위치에 남고 다시 잡으면 그 지점부터 이어서 당긴다. 실제 도르래 손실과 임의 개수의 복합 장치는 이후 확장 범위다.

### 4.5 Collision

객체가 서로 겹치는 경우 충돌 법선과 상대 속도를 계산하고 impulse를 적용한다.

현재 원–원, 원–회전 상자, 회전 상자–회전 상자 충돌과 반발계수(restitution)를 사용한다. 원은 반지름, 상자는 반너비·반높이와 선택적 회전각을 collider로 전달한다. 상자끼리는 두 상자의 로컬 축을 사용하는 SAT로 최소 침투축을 구하고, 원은 상자의 로컬 좌표에서 최근접점을 구한 뒤 접촉 법선을 월드 좌표로 돌린다. 받침대·벽·빗면은 별도 종류가 아니라 하나의 `fixed` 고정 블록이다. 사용자는 멈춘 상태에서 위치를 옮기고 손잡이로 가로·세로 크기를 바꾸거나 위쪽 회전 손잡이로 각도를 15°씩 맞출 수 있다.

반발계수와 마찰계수는 엔진 내부 물리량으로 유지하되 Playground에서는 직접 노출하지 않는다. 사용자는 고무, 나무, 금속, 점토 같은 교육용 재질 프리셋을 선택하고, 각 재질이 내부 계수로 변환된다. 이 재질은 실제 물질의 모든 성질을 재현하는 것이 아니라 충돌과 미끄러짐 반응을 쉽게 예상하게 하는 단순 모델이다.

자유 놀이터의 접촉면 마찰은 모든 법칙과 장의 합력을 계산한 뒤 `SurfaceContactFrictionModifier`에서 적용한다. 멈춘 물체에는 `|Fₜ| ≤ μₛN`인 접선 방향 힘을 상쇄하는 정지 마찰을, 움직이는 물체에는 `Fₖ = μₖN`인 운동 마찰을 적용한다. 운동 마찰은 한 프레임 안의 정지 힘으로 제한해 속도를 반대 방향으로 뒤집지 않는다. 기본 바닥은 움직이는 물체의 계수를 사용하고, 고정 블록은 움직이는 물체와 블록 계수의 기하평균 `μ접촉 = √(μ물체 μ표면)`을 사용한다. 고정 블록에서는 충돌과 같은 회전 상자 접촉 법선을 재사용하므로 바닥·옆면·빗면 모두 실제 접선 방향으로 마찰이 작용한다.

현재 월드 단위 역학 법칙은 실행 중에 추가·제거할 수 있다.

- `AnchoredSpringLaw`: 특정 물체와 고정점을 연결해 `F = -kx - bv`를 적용한다.
- `ConstantBodyForceLaw`: 특정 물체에 사용자가 화살표로 정한 일정한 힘 벡터를 적용한다.
- `SurfaceContactFrictionModifier`: 자유 놀이터 바닥과 고정 블록 접촉면의 재질별 정지·운동 마찰을 합력에 적용한다. 직접 밀기 모델을 따로 가진 마찰 실험 물체는 중복 적용하지 않는다.
- `HorizontalSurfaceFrictionLaw`: 특정 물체가 평평한 바닥에 닿았을 때 `F = μN`을 적용한다. 한 프레임 안에 정지할 수 있는 힘으로 상한을 두어 저속에서 운동 방향이 뒤집히지 않게 한다.
- `PushFrictionLaw`: 사용자가 주는 수평 힘을 최대 정지 마찰력과 비교하고, 한계를 넘은 뒤에는 운동 마찰력을 적용한다. 정지 직전에는 한 프레임의 정지 힘으로 제한해 방향이 반복해서 뒤집히지 않게 한다.
- `BuoyancyRegionLaw`: 원형 물체가 물에 잠긴 비율에 따라 아르키메데스 부력과 유체 저항을 적용한다.
- `BuoyancyAreaLaw`: 자유 놀이터의 수평 물 영역에 들어온 원·상자 모두에 모양과 잠긴 비율을 반영한 부력과 유체 저항을 적용한다.

Playground의 용수철 고정 마운트는 물체 반지름보다 작은 거리로 관통할 수 없다. 이전 위치와 다음 위치 사이의 선분을 검사해 한 프레임 안에 마운트 반대편까지 건너뛰는 빠른 운동도 감지하며, 접촉 시 고정점 안쪽 속도 성분만 제거한다.

`PhysicsSimulation.refreshAccelerations()`는 시간을 진행하지 않고 현재 법칙과 장을 다시 계산한다. 사용자가 물체를 드래그하거나 환경·재질을 바꾼 직후에도 가속도 화살표가 현재 상태를 가리키는 데 사용한다.

## 5. Simulation Pipeline

물리 시뮬레이션의 실행 순서는 명확하게 분리한다.

```text
1. Force Evaluation
   Laws + Fields
        ↓
2. Net Force Modification
   Surface-contact static / kinetic friction
        ↓
3. Integration
   Solver
   F → a → v → x
        ↓
4. Constraints
        ↓
5. Collision
        ↓
6. Advance Time
```

이 순서는 중요한 아키텍처 규칙이다.

특히 이전 구현에서 사용했던 작은 timestep을 이용한 임시 충돌 처리나 시간 rollback 같은 우회 방법은 사용하지 않는다. 충돌과 제약조건은 명시적인 pipeline 단계에서 처리해야 한다.

## 6. Solver

현재 코어에는 기본 Euler 계열 적분 구조가 있다.

향후 Solver를 교체 가능한 전략으로 확장한다.

```text
Solver
├── Euler
├── Semi-Implicit Euler
├── Verlet
└── RK4
```

목적은 물리 정확도 자체를 무조건 높이는 것이 아니라, 각 시뮬레이션 상황에서 안정성과 이해 가능성을 확보하는 것이다.

## 7. 테스트 원칙

물리 공식과 핵심 엔진 기능은 구현과 함께 테스트한다.

현재 테스트 범위에는 다음이 포함된다.

- 다중 객체의 힘 적용
- 충돌 impulse
- 거리 constraint
- 균일 중력장
- 점질량 중력장
- 균일 전기장
- 균일 자기장
- 방사형 field 계산

향후 모든 물리 법칙은 가능한 경우 다음 구조를 따른다.

```text
법칙 구현
   ↓
공식 단위 테스트
   ↓
시뮬레이션 통합 테스트
   ↓
시각적 Playground 검증
```

## 8. 브라우저 Playground

웹 애플리케이션은 물리 코어와 UI를 분리한다.

```text
src/
├── physics/
│   ├── core.ts
│   ├── quantities.ts
│   ├── world.ts
│   ├── fields.ts
│   ├── simulation.ts
│   └── laws/
│
└── app/
    ├── mechanics-labs.ts
    ├── mechanics-challenges.ts
    ├── physics-playground.ts
    ├── mechanics-scenes.ts
    ├── main.ts
    └── style.css

index.html
```

`PhysicsPlayground`는 브라우저 입력과 Canvas 렌더링을 물리 코어에 연결하는 adapter 역할을 한다.
`mechanics-labs.ts`는 각 역학 실험의 질문, 세 단계 조작, 관찰 포인트, 허용 조건을 정의한다. UI는 이 정의를 사용하고, Canvas adapter가 실험 콘텐츠 문구를 직접 소유하지 않도록 한다.
`mechanics-challenges.ts`는 지렛대의 토크 평형, 도르래의 역학적 이득, 궤도 결과 예측을 Canvas와 분리해 계산한다. 직접 조작 UI는 이 작은 계약만 사용하므로 계산 모델을 렌더링 없이 회귀 테스트할 수 있다.
`PhysicsPlayground`의 snapshot은 현재 실험에 맞는 시계열 측정값을 함께 제공하고, `lab-graph.ts`는 이 데이터만 받아 안내 패널의 선 그래프를 그린다. 자유 놀이터에서는 선택한 움직이는 물체 하나의 속력을 같은 그래프 계약으로 제공하며, 선택이 바뀌면 이전 물체의 시계열을 지운다.

현재 웹 애플리케이션은 하나의 `실험 선택` 목록에서 같은 물리 코어를 사용하는 두 작업 상태를 제공한다. 자유 놀이터는 별도 상위 탭이 아니라 안내형 실험과 같은 레벨의 `빈 실험실 만들기` 항목으로 진입한다.

- **역학 실험실**: 준비된 장치, 탐구 질문, 세 단계 조작, 관찰 포인트를 제공하고 실험과 관계없는 편집 기능을 숨긴다.
- **자유 놀이터**: 움직이는 공·상자와 크기를 직접 바꾸는 고정 블록을 추가·삭제하고 연결·힘·장치·환경을 조합할 수 있는 샌드박스다.

현재 지원하는 기능:

- 별도 실험 선택 화면과 반응형 3패널 실험 화면: 설정 / 물리 월드 / 설명·관찰·그래프
- 어린이도 바로 사용할 수 있는 행동 중심 문구와 큰 선택 버튼
- 재질·무게는 쉬운 프리셋을 기본으로 제공하고 정확한 수치 입력은 접어서 숨기는 점진적 공개
- 법칙 이름만 바꾼 시작 상태가 아니라 서로 다른 탐구 질문과 관찰 목표를 가진 10개 역학 실험
- 움직임과 힘: 자유 낙하, 포물선, 충돌·운동량·충격량, 용수철·에너지, 마찰
- 회전과 연결: 회전·토크, 진자·줄·막대, 도르래
- 중력과 유체: 원운동·만유인력·궤도, 부력
- 실행 / 일시정지 / 단일 프레임 진행 / 초기화
- 자유 놀이터의 공·상자·고정 블록 팔레트와 선택, 드래그, 삭제
- 자유 놀이터의 고정점, 줄·막대 연결, 방향과 세기를 직접 끌어 조절하는 힘 화살표
- 여러 용수철, 지렛대와 도르래의 동시 배치, 이동 가능한 점중력원과 물 영역
- 원–원, 원–회전 상자, 회전 상자–회전 상자 충돌과 고정 블록 위 정지
- 역학 실험실 장치의 추가·삭제 방지와 실험별 관련 조건만 노출
- 고정 블록의 가로·세로·모서리 크기 손잡이, 15° 회전 손잡이와 collider 동기화
- 선택 물체의 이름, 색상, 질량, 재질 편집과 운동 화살표 조작
- 무중력, 달, 지구, 목성 중력 환경 선택
- 바닥·천장·좌우 벽 경계 충돌
- 부딪히기 빠른 시작의 약한 운동 감쇠와 저속 정지 처리
- 고정점·코일·평형 위치를 표시하는 감쇠 용수철 운동
- 직접 미는 힘과 최대 정지 마찰력의 임계점, 재질에 따른 운동 마찰과 저속 정지 처리
- 운동량 화살표와 충돌 순간의 충격량 피드백
- 용수철 체험 안에서만 표시되는 운동 에너지·용수철 에너지 상대 막대
- 중심 가속도, 지렛대 토크 평형, 진자 복원력, 점중력장, 부력, 줄 길이 보존, 도르래의 힘·거리 교환
- 이동 궤적과 속도·가속도 벡터
- 실험별 `질문 → 이렇게 해보세요 → 눈여겨볼 것` 안내와 대표 공식
- 10개 역학 실험별 핵심 물리량과 자유 놀이터 선택 물체의 속력을 제목·단위·범례·현재값과 함께 보여주는 실시간 그래프
- 자유 놀이터 선택 물체의 속력·가속도·운동량·운동 에너지·관련 위치 에너지·적용 힘 관찰값
- 속도·가속도 용어 설명과 속도 화살표의 조작 가능 여부 안내
- 고정 timestep과 SI 단위/화면 좌표 변환
- 키보드 조작: Space 실행/멈춤, 방향키 오른쪽 단일 진행, 자유 놀이터에서 Delete 삭제

설정 변경은 전체 월드를 자동 초기화하지 않는다. 역학 실험을 선택할 때만 해당 장치의 시작 상태를 불러오며, 실험 중 재질·무게·중력 변경은 현재 상태에 즉시 적용한다. 자유 놀이터에서는 움직이는 물체의 재질과 고정 블록의 표면 재질 변경이 접촉면의 정지·운동 마찰계수를, 중력 변경이 바닥 수직항력을 즉시 갱신한다. 고정 블록 크기나 각도를 바꾸면 Canvas 모양과 상자 collider의 반너비·반높이·회전각이 즉시 함께 갱신된다. 운동 화살표나 블록 크기·회전 손잡이를 조작할 때는 재현 가능한 관찰을 위해 시뮬레이션을 자동으로 일시정지한다.

역학 실험실과 자유 놀이터는 사용자에게 하나의 실험 선택 목록으로 보이지만 내부 작업 상태와 허용 조작은 분리하며 별도 물리 엔진을 복제하지 않는다. 실험실은 교육 콘텐츠와 허용 조작을 소유하고, 자유 놀이터는 일반 월드 편집과 고정점·줄·막대·힘·재사용 가능한 용수철·지렛대·도르래·중력원·물 팔레트를 소유하며, 둘 다 `PhysicsPlayground`와 테스트 가능한 물리 코어를 재사용한다. `빈 실험실 만들기`를 선택하면 이전 실험 장치를 제거하고 지구 중력과 원 하나를 가진 깨끗한 월드로 시작한다. 사용자는 첫 물체를 선택하고 `줄` 또는 `막대`를 누른 뒤 두 번째 물체나 고정점을 선택해 두 중심 사이의 현재 거리를 보존하는 `DistanceConstraint`를 만든다. 연결 대기 중에는 종류에 맞는 미리보기를 표시하고, 끝점 삭제와 새 월드 시작 시 관련 제약도 함께 정리한다. 힘 화살표와 점중력장은 각각 고유한 법칙·장을 가지며 물체를 삭제하면 함께 정리한다. 물은 월드 전체의 수평 영역 법칙으로 켜고 끈다. 용수철은 선택한 움직이는 물체마다 하나씩 연결할 수 있고, 지렛대와 도르래는 같은 월드에 함께 둘 수 있다. 장치를 추가해도 일반 물체와 사용자 연결은 보존한다.

반복 조작에서 실행 버튼을 매번 누르지 않도록 사용자가 역학 실험을 선택하거나 `처음으로`를 누르면 상태를 준비한 뒤 자동 재생한다. 단, 페이지를 처음 연 직후의 자유 낙하는 세 공의 시작 위치가 새로고침 시점에 따라 달라 보이지 않도록 대기 상태로 둔다. 속도 화살표에 유효한 속도를 지정하고 놓으면 즉시 발사하며, 용수철에 연결된 물체도 당겼다 놓으면 바로 움직인다. 마찰·지렛대·도르래는 실행 버튼과 관계없이 Canvas 손잡이를 잡는 순간 바로 반응한다. 자유 놀이터 진입과 일반 물체 배치는 멈춘 상태를 유지해 의도하지 않은 재생을 피한다.

지렛대는 막대만 그리지 않고 삼각 받침대, 축, 짐 접촉판, 세 힘점, 거리 눈금, 누르는 손잡이를 하나의 장치로 표시한다. 손잡이를 누르는 동안 힘은 성공에 필요한 기준까지 증가하고, 성공한 뒤에는 적용 힘과 손잡이 이동을 그 기준에 고정해 과도한 힘이 성공값처럼 보이지 않게 한다. 도르래는 1줄에서 고정도르래의 방향 전환을, 2줄에서 움직도르래 하나를, 4줄에서 위·아래 도르래 묶음을 실제로 이어진 줄 경로로 그린다. 모든 경우 빨간 손잡이와 짐이 같은 줄 계통 안에서 읽혀야 한다.

진자·줄·막대는 `mechanics-scenes.ts`의 렌더러 독립 운동 모델을 사용한다. 지렛대와 도르래는 `mechanics-challenges.ts`의 정적 평형 모델을 사용해 힘점을 옮기거나 받치는 줄 수를 바꿀 때 필요한 힘과 이동 거리를 즉시 다시 계산한다. 원운동은 별도 카드로 반복하지 않고 점중력 궤도 체험에서 중심 가속도와 함께 관찰한다.

만유인력·궤도는 `PointGravityField`와 기본 Euler 적분기를 실제로 통과한다. 속도 손잡이를 바꾸면 `OrbitChallenge`가 같은 중력 매개변수로 예상 경로를 미리 적분하고 충돌·공전·이탈을 판정한다. 따라서 색 점선은 발사 선택을 비교하기 위한 예측이며 실제 경로는 수치 적분 오차에 따라 조금 달라질 수 있다. 더 긴 시간의 궤도 안정성이 필요해지면 Solver를 Semi-Implicit Euler 또는 Verlet로 교체한다.

현재 역학 실험실은 다음 제품 흐름을 구현한다.

```text
탐구할 실험 선택
  ↓
질문과 조작 단계 확인
  ↓
관련 물리 조건 변경
  ↓
장치 직접 조작·실행
  ↓
물리 모델 계산
  ↓
관찰 포인트·시각화 비교
  ↓
조건을 바꾸거나 자유 놀이터로 확장
```

## 9. Frontend Build

프론트엔드는 Vite + TypeScript 기반으로 구성한다.

```text
TypeScript
    ↓
Vite
    ↓
dist/
    ↓
GitHub Pages
```

`vite.config.ts`의 Pages base 경로는 다음과 같다.

```text
/open-physics/
```

개발 명령:

```bash
npm install
npm run dev
```

빌드:

```bash
npm run build
```

테스트:

```bash
npm test
```

`package-lock.json`은 실제 npm dependency resolution 결과를 저장하며, CI와 로컬 검증은 동일한 의존성 버전을 사용한다. CI에서는 `npm ci`로 lockfile을 엄격하게 적용한다.

## 11. 교육 단계와 물리 법칙

Open Physics의 핵심 UX는 하나의 물리 공간에서 객체가 실제로 법칙의 영향을 받되, 사용자의 학습 단계에 따라 활성화되는 법칙의 범위를 조절하는 것이다.

예:

```text
초기 역학
→ 중력 + 기본 운동

확장 역학
→ 힘 + 마찰 + 스프링 + 충돌

전자기학
→ 전하 + 전기장 + 자기장

파동
→ 파동장

빛
→ 광선 + 반사 + 굴절

현대물리
→ 광자 + 원자 + 핵 + 상대론적 모델
```

중요한 것은 서로 다른 앱을 만드는 것이 아니라 **동일한 물리 공간에서 활성 법칙 집합만 변경하는 것**이다.

## 12. 향후 개발 우선순위

현재 단계 이후의 우선순위는 다음과 같다.

2. 충돌 시스템 강화

4. 물리 객체 생성 및 편집 UX 개선
5. 프리셋 시스템
6. 법칙 활성화 단계 시스템
7. 역학 콘텐츠 확장
8. 전자기학 / 파동 / 빛 / 열 / 현대물리 확장
9. 시각화 요소 강화
10. 교육용 실험 시나리오 추가

## 13. 개발 원칙 요약

```text
물리 공식
   ↓
독립적인 Law / Field
   ↓
PhysicsSimulation
   ↓
Solver Pipeline
   ↓
물리 상태
   ↓
Renderer
   ↓
사용자 인터랙션
```

물리 엔진과 콘텐츠 설명을 섞지 않는다.

물리 공식은 테스트 가능한 코드로 만든다.

시뮬레이션은 백엔드 없이 브라우저에서 실행한다.

웹 2D는 유지보수만 하고, 새 실험 공간은 3D 앱에서 만든다. 3D에서도 안내형 실험의 핵심 운동과 표시 수치는 공식 코어 값으로 보정한다.

교육과정은 콘텐츠 구조를 위한 참고자료이지 물리 엔진의 구조적 제약이 아니다.
