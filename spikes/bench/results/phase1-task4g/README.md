## 3. 헤드리스 확인 (요약)

자세한 항목은 [앱 README 테스트 표 "빵고양이"](../../../../apps/lab3d/README.md#3-빌드와-테스트)에 있다.

던지기:
- 발사 프레임의 손-공-발사점 오차는 2.4e-7 m다(허용 1e-4).
- 놓기 전 손과 보이는 공의 차이는 0 m다.
- 발사 뒤 엔진 위치·패널은 직접 놓기와 같다(9가지 조건, 3초).
- 높이 0–3 m에서 손 = 발사점이고, 빵 상자 윗면 = 고양이 바닥이다.
- 오버핸드(높이 0.5–3 m × 0·15·45·75°): 놓는 손이 어깨 위이고, 휘두르는 속력이 계속 늘며, 놓기 직전 1/60초 손 방향과 발사 방향의 차이는 0°다(허용 10°).

마찰 밀기:
- 앞발과 상자 면의 간격은 4.8e-7 m다.
- 고양이가 있든 없든 상자 운동과 패널 값이 720스텝 동안 같다.

작업 전 커밋과의 로그 비교(최종 HEAD 코드, 2026-10-23 19시):
- 비교 대상은 17a9c79(+ 문서 커밋 3aeab4f, 코드 같음)다.
- 던지기 6가지 × 240스텝, 마찰 밀기 2가지 × 360스텝의 엔진 위치와 패널 값을 비교했다.
- 마찰 밀기 720줄이 모두 같다.
- 던지기는 같은 스텝 1,366줄이 모두 같다. 던지기 기록은 발사 프레임부터 스텝 번호로 맞췄다.

돌연변이의 실패를 확인하고 원복했다.
- 빵고양이 7종: 손 2 mm, 발사 1프레임 늦음(놓기 프레임 검사를 정확히 28프레임으로 바꾼 뒤), 발사 3프레임 늦음, 팔 2 % 늘어남, 앞발 3 mm, 고양이 아래 바디, 휘두르기 마지막 직선 29° 틀어짐
- 던지는 도중 각도·빠르기·중력을 바꾸거나 화면을 재구성해도 늦은 놓기가 없고, 고양이가 발사점에서 공을 든다(시험 추가)
- 털실 공 1종: 공 색 1 % 틀림

털실 공·택배 박스로 바꾼 뒤에도 앱 전체 시험이 통과한다. 운동·패널·parity 값은 그대로다.

## 4. 처음으로 버그 (2026-10-23 사용자 보고 "전부 다 안됨")

SM-P200 증상: 처음으로를 누르면 패널·시계는 처음으로 돌아가지만, 몸체가 돌던 자리에 남았다. 던지기 공·고양이, 자유 낙하 공, 용수철 공, 진자 추, 충돌 공에서 확인했다. 버튼 자체는 눌렸다(로그로 확인).

원인: 버튼 입력(물리 스텝 밖)에서 옮긴 얼린 몸체를 Jolt가 다음 스텝의 이동으로 다룬다. 그 스텝의 상태 동기화가 진행 중이던 스텝의 자세를 보고해 노드가 옛 자리로 돌아간다.
- 서버 상태를 직접 바꿔도 같았다.
- 한 프레임에 스텝이 1번인 헤드리스 `--fixed-fps` 시험에서는 생기지 않아 지금까지 잡히지 않았다.
- 실시간 헤드리스, 또는 스텝 없는 프레임을 섞은 경우(초당 20스텝)에는 용수철 1.66 m, 진자 0.42 m, 충돌 2.57 m가 처음 자리로 돌아오지 않았다.
- 17a9c79 코드에서도 같은 값으로 재현됐다(origin/dev부터 있던 버그).

수정: `BodyResync`가 변경이 옮긴 몸체를 다음 고정 스텝 맨 앞(동기화 뒤, 엔진 스텝 전)에서 한 번 더 놓는다.
- 스텝 안에서 옮긴 이동은 남는다(시험으로 확인).
- 처음으로는 연출(커지며 나타나기) 없이 바로 쉬는 자세가 되고, 카메라는 화면을 연 시점으로 바로 스냅한다.
- 기기에서 던지기·자유 낙하·용수철·진자·충돌 모두 누른 뒤 0.1초에 처음 자세임을 확인했다.
- 회귀 시험은 `tests/reset_checks.gd`다(11개 실험, 실제 터치, 스텝 없는 프레임).

## 6. 남은 일·판단 필요

- 큰 머리 때문에 생기는 겹침과 가림:
  - 낮은 각도(0–15°) 던지기에서는 휘두르기 끝에 공이 볼 옆을 스친다.
  - 감기는 머리 뒤로 가서 정면에서는 일부 가려진다.
- 던지기 정점 예산 초과(약 16,100, 3 m에서 약 17,600 / 15,000): 문서 예외로 두었다(fps 충족).
- 대기 변형(눕힌 봉투)과 다른 실험 확장은 이번 범위 밖이다.
