## 리뷰 반영 뒤 재측정 (2026-10-26 오후)

리뷰 반영(앵그리버드식 새총, 판정 시점, 대화창 질문, 지도 성능 등) 빌드를 같은 기기·같은 절차(`bench_device.sh low 3 90 60`, 10분 지속 측정 생략)로 다시 쟀다. 홈은 새로 넣은 `OPBENCH_EXPERIMENT=home`(앱을 `--quality=low`로 열어 지도에서 측정, 장면 이름 `home`), 던지기는 `--auto-drag=4`다. 던지기 데모는 이제 4초마다 공을 실제로 당겼다 놓는다(새총 손가락 경로; G5 측정 때의 데모는 공을 눌러 두기만 하고 다음 누름에서야 던졌다). 측정 중 던지기는 아이 도장 대신 `user://progress-bench.cfg`에 저장한다.

### 홈(섬 지도)

| 묶음 | Run별 평균 fps | 합 | GPU 클럭(5초 표본) |
|---|---|---|---|
| `home-review` | 59.74 / 59.71 / 59.74 | **59.73 통과** | 545–845 MHz |
| `home-first-after-install` | 52.78 / 52.72 / 52.71 | 52.74 | 450 MHz 고정(74/77) |

OPPERF(통과 묶음): draws 62, prims 12,902, objects 103. 지도는 진행 파일을 열 때 한 번만 읽는다(G5 빌드는 매 프레임 장소 11곳마다 `ProgressStore.load()`).

지도 요소를 하나씩 끈 빌드(라벨·상단 바·빵고양이·장소·섬 전체)로도 재 보았다(각 40초). GPU가 450 MHz에 묶이지 않은 때에는 모든 경우가 59.98–59.99 fps라 지도 내용 중 한 가지가 60 fps를 막는 것은 아니었다.

### 던지기 (PJ)

| 묶음 | Run별 평균 fps | 합 | GPU 클럭 |
|---|---|---|---|
| `projectile-review` | 59.60 / 59.53 / 59.59 | **59.57 통과** | 545–845 MHz(450은 4/75) |
| `projectile-first-after-install` | 48.03 / 47.73 / 48.01 | 47.92 | 450 MHz 고정 |
| `projectile-second-degraded` | 48.03 / 48.12 / 47.99 | 48.05 | 450 MHz 고정 |
| `projectile-third` | 59.20 / 48.14 / 47.91 | 51.78 | Run 1 545–845 MHz, Run 2·3 450 MHz 고정 |
| `projectile-g5-build-ab` (G5 커밋 `0120618` 빌드) | 48.50 / 48.57 / 48.61 | 48.56 | 450 MHz 고정 |

OPPERF(통과 묶음): draws 59.6, prims 31,412, objects 147. 기기를 10분쯤 쉬게 한 뒤 다시 설치하고 쟀다.

### 450 MHz 고정 상태

- 미달 묶음은 모두 Mali GPU 클럭이 450 MHz에 묶여 있었다. 그때 `/sys/class/misc/mali0/device/utilization`은 99, `clock`은 450000이었다(최대 잠금; 잠금 상태 파일은 권한이 없어 읽지 못함). 통과 묶음은 545–845 MHz였다.
- 같은 시각에 G5에서 59.62로 통과했던 G5 빌드도 48.56이었다. 그래서 이번 변경 때문이 아니라 기기 상태라고 본다. 설치 직후와 연속 측정 뒤에 생겼고, 몇 분 쉬면 풀렸다. 원인(삼성 전력·발열 정책 등)은 확인하지 못했다. AP 온도는 41–45 °C로 통과 묶음과 비슷했다.
- 기기 설정(화면 꺼짐, 밝기, 전원 정책)은 바꾸지 않았다.
