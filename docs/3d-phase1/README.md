# Phase 1 — 역학 3D 앱 첫 출시

> **Status:** 진행 중
> **시작:** 2026-10-21
> **근거:** [ADR 0001: Godot 4 + Jolt](../adr/0001-3d-app-stack.md) · [Phase 0 측정 기준](../3d-phase0/benchmark-spec.md)

Notion Story·Task와 GitHub Issue는 발행하지 않는다. 이 문서가 Phase 1의 계획과 진행 기록을 대신한다. Task를 시작하거나 마칠 때 아래 표의 상태·브랜치·PR을 갱신한다.

## 목표

역학 영역(안내형 실험 10개 + 빈 실험실)을 Godot 4 + Jolt 기반 3D 앱으로 만들어 iOS·Android 스토어에 첫 출시한다. 웹은 같은 콘텐츠를 Compatibility 렌더러로 제공한다.

## 출시 기준

- 성능: 하한 기기 SM-P200에서 저품질 60 fps, 중급폰에서 고품질 60 fps. 10분 사용 시 스로틀링·메모리 증가가 없어야 한다.
- 교육 정확도: 안내형 실험의 핵심 운동과 표시 수치가 TS 공식 코어 값과 일치해야 한다(공식 보정). parity 테스트로 확인한다.
- 정책: 무료·무광고·아동 포함. 계정·서버·제3자 추적을 두지 않는다.

## Task 2b 상세

**의도**: 3D에서도 2D만큼 쉽게 물체를 집어 옮기고 놓을 수 있게 한다. 아동이 화면을 손가락 하나로 끌어도 물체가 엉뚱한 깊이로 날아가지 않도록, 정해진 면(바닥·빗면 등) 위에서만 움직이고 높이는 따로 조절한다. 안내형 실험과 빈 실험실(Task 5)이 같은 조작을 쓴다.

**결정사항** (Phase 0 grilling, 2026-10-21)
- 조작 평면(바닥·면 위 드래그) + 스냅 + 자동 안착 + 보조 시점, 높이는 별도 손잡이.
- 빈 곳 한 손가락 드래그는 카메라 회전에 쓰지 않는다(2a에서 `View3D.single_pointer`로 비워 둠).

**범위**
- 포함
  - 셸 공용 조작 모듈: 터치/마우스로 물체 집기(레이캐스트), 끌기 중 조작 평면(물체가 놓인 면 또는 바닥)에 투영, 놓기, 취소(`single_pointer` cancel 포함).
  - 스냅: 면 위 격자·눈금(실험이 정의), 놓을 수 있는 위치 미리보기(유령 메시·발밑 표시), 놓을 수 없는 위치 표시.
  - 자동 안착: 놓으면 면에 붙어 정지 상태로 내려앉음(연출은 2c 키트 재사용, 물리 결과 불변).
  - 높이 손잡이: 선택된 물체 옆 세로 손잡이로 높이만 조절(빈 실험실용; 안내형 실험은 실험이 허용할 때만).
  - 보조 시점: 끄는 동안 조작 평면이 잘 보이도록 카메라가 살짝 내려다보는 각도로 보정하거나 작은 보조 뷰(성능 예산 안에서, 실측으로 결정).
  - 실험 인터페이스: 어떤 물체가 조작 가능한지, 허용 면·스냅 규칙·높이 허용을 실험 JSON/스크립트가 정의.
  - 빗면 실험에 적용: 상자를 빗면 위 원하는 출발 위치로 끌어 놓기(빗면 위만, 눈금 스냅). 표시 수치(이동 거리 등)는 새 출발 위치 기준으로 계속 공식과 일치.
  - 검증용 개발 장면(목록에 노출하지 않음): 바닥 위 물체 여러 개로 바닥 평면·높이 손잡이·겹침 방지 확인.
- 제외: 빈 실험실 도구 팔레트·물체 생성(Task 5), 줄·용수철 연결, 다른 안내형 실험, 사운드·햅틱.

**판정**
- 실기기(SM-P200)에서 손가락 하나로 상자를 빗면 위 원하는 위치에 놓을 수 있다(스냅·미리보기·놓을 수 없는 곳 표시). 개발 장면에서 바닥 이동·높이 손잡이가 동작한다.
- 끄는 동안과 놓은 뒤 low 60 fps(측정 기준 절차 90초 × 3회, 끄기 재생 포함).
- 공식 보정·표시 수치 테스트 통과, 조작 회귀 테스트(투영·스냅·취소·두 손가락 전환 시 조작 취소).
- 화면 기록 또는 연속 스크린샷.

## Task 2c 상세

**의도**: 사용자 요청 "그래픽이 게임 같으면 좋겠어, 그래야 재밌지". 학생이 만지고 싶어지는 화면을 만든다. 하한 기기 low 60 fps 안에서 비싼 효과 대신 아트 스타일과 움직임으로 낸다. 정한 스타일은 이후 모든 실험의 기준이 된다.

**결정사항** (2026-10-21, 사용자)
- 스타일: 장난감·로우폴리. 둥글고 두툼한 물체, 밝은 파스텔·원색, 구운 조명과 발밑 그림자, 놓기·부딪힘에 통통 튀는 연출.
- 2a 다음, 2b보다 먼저 한다.
- (2026-10-22) 시안 A 놀이방 책상·B 잔디 섬·C 스튜디오 무대 중 **B 잔디 섬**(선명한 원색, 각진 로우폴리, 하늘에 뜬 잔디 섬)으로 확정. [시안 비교](../../spikes/bench/results/phase1-task2c/mockups/README.md)
- (2026-10-22) 기본 카메라를 빗면에 더 가깝게 해 상자와 연출이 잘 보이게 한다(상자 크기·물리는 그대로).

**범위**
- 포함
  - 시안: 빗면 장면에 스타일 시안 2~3개를 만들어 SM-P200 스크린샷으로 사용자에게 고르게 한다(색·형태·배경 환경 차이).
  - 선택안 확정: 공용 재질·색 팔레트·조명 구성(셸이 제공, 실험이 재사용), 로우폴리 소품(빗면 받침, 상자, 바닥·배경 환경), 발밑 그림자(블롭 또는 구운 그림자) — low에서도 그림자가 보이게.
  - 연출: 놓기·착지·멈춤의 짧은 반응(스쿼시·스트레치, 작은 먼지 입자, 카메라 미세 반응), 버튼·전환 애니메이션. 물리 결과와 표시 수치는 바꾸지 않는다(연출은 보이는 메시에만).
  - 2D 패널을 새 스타일에 맞춘 색·모서리·아이콘 조정(웹 2D 계승 범위 안).
  - 스타일 가이드 문서(`apps/lab3d/docs/art-direction.md`): 팔레트, 형태 규칙, 조명, 연출 규칙, 성능 예산.
- 제외: 사운드·햅틱(필요하면 별도 합의), 다른 실험, 조작 평면(2b).

**판정**
- 사용자가 시안 중 하나를 고른다.
- SM-P200 low에서 빗면 실험 60 fps(측정 기준 절차 90초 × 3회, 10분 지속 1회).
- 공식 보정·표시 수치 테스트가 그대로 통과한다.
- 스타일 가이드와 전후 스크린샷.

## Task 2a 상세

**의도**: 역학 3D 실험을 하나씩 끼워 넣을 앱의 뼈대를 만든다. 실험이 공통으로 쓰는 카메라·제스처·2D 패널·품질 설정을 셸이 맡고, 실제 실험 하나(빗면 마찰)를 올려 셸이 실험 요구를 감당하는지 확인한다. 조작 평면은 2b로 미룬다.

**결정사항** (2026-10-21, 사용자)
- Task 2를 2a(뼈대)와 2b(조작)로 나눈다.
- 셸 검증 장면은 빗면 마찰 1개를 실제 실험으로 이식한다. Task 4의 첫 실험이 된다.
- UI 시각 스타일은 웹 2D(`src/`의 색·글꼴·패널 구성)를 계승해 Godot 테마로 옮긴다. 기준은 [PRODUCT_GUIDELINES](../PRODUCT_GUIDELINES.md)다.

**범위**
- 포함
  - `apps/lab3d/` Godot 4.7.2 + Jolt 프로젝트. `spikes/godot/`의 품질 단계·측정 로그(OPBENCH/OPPERF)·parity 테스트·빌드 스크립트를 옮겨 쓴다. 스파이크는 참고용으로 그대로 둔다.
  - 실험 목록 화면 → 실험 화면 흐름. 실험은 정해진 인터페이스(장면, 기본 시점·회전 범위, 조건 조절 항목, 관찰값, 그래프)로 등록한다.
  - 카메라 모드 6종과 항상 보이는 "정면으로" 버튼. 실험별 기본 시점과 회전 범위.
  - 터치 제스처: 두 손가락 회전·확대/축소·이동. 빈 곳 한 손가락 드래그는 회전에 쓰지 않는다(2b의 조작용).
  - 2D 패널: 설명, 조건 조절, 관찰값, 그래프. 폰 세로와 태블릿 가로 레이아웃.
  - 품질 단계 설정 화면. low에서도 UI는 원본 해상도로 선명하게 그린다(3D만 낮은 해상도). 방식은 실측으로 정한다.
  - 빗면 마찰: 각도·마찰 계수 조절, 정지 마찰 임계각·가속도 표시, 공식 보정(스파이크 S3 방식), 웹 2D 실험 내용 기준.
- 제외: 조작 평면·스냅·높이 손잡이(2b), 다른 실험, 공식 보정 계층 일반화와 CI(Task 3), 스토어·iOS.

**판정**
- SM-P200 low에서 빗면 실험 60 fps(측정 기준 절차, 패널·그래프 표시 상태).
- 카메라 모드·"정면으로"·제스처가 실기기에서 동작한다(화면 기록 또는 스크린샷).
- 폰 세로·태블릿 가로 레이아웃 스크린샷. low에서 UI가 원본 해상도로 그려진다.
- 헤드리스 테스트(parity, 빗면 공식 일치)가 통과한다.

## Task 1 상세

**의도**: Godot을 채택했지만 Phase 0에서 S2(물체 50개 빈 실험실)가 하한 기기 11.6 fps로 세 장면 중 가장 느렸다. 출시 기준(하한 기기 저품질 60 fps)에 닿을 수 있는지를 앱 셸을 만들기 전에 확인한다.

**범위**
- 포함: `spikes/godot/`에서 S2 병목 측정, 저·중·고 품질 단계 구현, SM-P200 실측, 결과 문서
- 제외: 앱 셸(`apps/`) 작성, 새 실험 콘텐츠, iOS

**방법**
1. 재현 루프를 만든다. 고정 조건(같은 seed, 같은 카메라)의 S2를 60초 측정한다. 프레임 시간과 함께 Godot 모니터(CPU 처리·물리 시간, GPU 렌더 시간, 드로우콜·프리미티브 수)를 기록한다.
2. 변수를 하나씩 바꿔 병목을 가른다. 후보는 그림자(모드·크기·끔), MSAA, 3D 해상도 배율, 드로우콜(물체 50개 개별 메시 vs MultiMesh), Jolt 스텝(물리만 실행), 환경광·후처리다.
3. 결과로 품질 단계를 정한다. 저품질은 하한 기기 60 fps를 목표로, 고품질은 Phase 0 수준의 그래픽을 유지한다.
4. 단계별로 S1~S3를 측정 기준 절차로 측정한다(S2 10분 지속 포함).

**판정**
- 저품질에서 S1~S3가 SM-P200 60 fps에 닿으면 Task 2로 간다.
- 닿지 못하면 남은 병목과 차이를 보고하고, 기기 기준이나 그래픽 목표를 사용자와 다시 합의한다.
