# 아트 디렉션 — 잔디 섬 스타일

Phase 1 Task 2c에서 정한 3D 앱의 시각 기준이다. 사용자가 시안 셋 중 **B 잔디 섬**(선명한 원색, 각진 로우폴리, 하늘에 뜬 잔디 섬)을 골랐다([시안 비교](../../../spikes/bench/results/phase1-task2c/mockups/README.md)). 이후 실험은 모두 이 문서를 따른다. 목표는 학생이 만지고 싶어지는 "게임 같은" 화면을 비싼 효과 없이 내는 것이다. 하한 기기(SM-P200) low에서 60 fps가 먼저다.

코드: `scripts/art/`(셸 공용), `experiments/<실험>/<실험>_props.gd`(실험별 소품).

| 파일 | 역할 |
|---|---|
| `scripts/art/art_palette.gd` (`ArtPalette`) | 3D와 2D가 함께 쓰는 색 |
| `scripts/art/art_mesh_builder.gd` (`ArtMeshBuilder`) | 코드로 만드는 로우폴리 메시(모서리 깎은 상자, 원기둥·원뿔, 구, 블롭 그림자) |
| `scripts/art/art_lit.gdshader` | 구운 조명(색 램프), sRGB 처리 |
| `scripts/art/art_kit.gd` (`ArtKit`) | 공용 재질, 그림자 재질, 환경(하늘색 배경), 떠 있는 잔디 섬 |
| `scripts/art/art_juice.gd` (`ArtJuice`) | 움직이는 몸체 하나의 연출(튀어나옴·늘어남·착지·멈춤)과 따라다니는 블롭 그림자 |
| `scripts/app/ui_theme.gd`, `island_banner.gd` | 2D 패널 테마, 목록 화면 머리 그림 |
| `experiments/incline_friction/incline_props.gd` (`InclineProps`) | 빗면 실험의 소품(빗면·받침·상자·출발선)과 연출 연결 |

## 1. 원칙

- 보이는 것만 바꾼다. 물리 바디·충돌 모양·공식 보정·표시 수치는 아트와 무관하다. 소품은 바디 아래의 `MeshInstance3D`이고, 연출은 그 메시의 `scale`·`position`만 바꾼다. 헤드리스 테스트가 확인한다(5절 끝).
- 엔진 조명·실시간 그림자를 쓰지 않는다. 밝기는 셰이더의 색 램프, 접촉감은 정점 AO와 블롭 그림자로 낸다. 그래서 low(Compatibility)와 high(Mobile)가 같은 모습이다.
- 외부 에셋 없이 코드로 만든다. 정적인 것은 메시 하나로 합친다(드로우콜 예산, 8절).
- 전체 화면을 덮는 반투명 레이어를 만들지 않는다. SM-P200은 원본 해상도 전체 화면 레이어 하나로 60 fps를 잃는다([UI 해상도 결정](ui-resolution.md)).

## 3. 형태 규칙

- **각진 로우폴리**: 면마다 법선 하나(`ArtMeshBuilder.flat = true`가 기본). 둥근 것도 면이 보이게 적게 나눈다. 원기둥 6–8면(나무·받침 발 8, 섬 14), 구는 고리 3–4 × 둘레 5–7.
- **면별 단색**: 부품 하나에 색 하나. 위를 향한 면(법선 y > 0.7)만 `*_TOP` 색으로 조금 밝게 한다(`top_color`). 무늬·텍스처를 쓰지 않는다.
- **모서리 깎기**: 상자는 `add_rounded_box(radius 0.05, segments 1)` — 둥글게가 아니라 한 번 깎은 모서리. 반지름은 짧은 변의 10–15%를 넘기지 않는다. 예외: 빗면 0.06, 받침 기둥 segments 2, 출발선 같은 얇은 표식은 비율 규칙을 따르지 않는다.
- **두께**: 장치는 실제보다 두툼하게 보인다. 빗면은 충돌 상자 0.3 m보다 두꺼운 0.5 m로 그리되 **윗면은 충돌 면과 같은 높이**로 두고 아래로만 늘린다(물체가 떠 보이지 않게). 받침 기둥은 0.5 m 각기둥 + 지름 1.5 m 발. 빗면이 기울면 기둥 윗면이 빗면을 뚫고 보이지 않도록 기둥을 세로로 줄인다(`InclineProps.stand_height`, 빗면 아랫면 0.04 m 아래, 최대 45°에서도).
- **크기**: 물리 크기를 바꾸지 않는다(상자 0.4 m). 작아 보이면 카메라를 당긴다(6절 카메라).
- **정점 AO**: 모든 모양은 바닥 쪽이 어둡다. `ao_min`(바닥 밝기 배율, 0.7–0.95)과 `ao_height`(밝아지는 높이, m)로 정한다. 땅에 닿는 작은 것은 0.75–0.85, 큰 땅덩이는 0.95.

## 4. 조명·셰이더

`art_lit.gdshader`(재질은 `ArtKit.lit_material()` 하나를 모두 공유):

- `render_mode unshaded`. 엔진 조명·그림자·환경광을 받지 않는다.
- **색 램프**: 정점 단계에서 `wrap = dot(N, sun_dir) × 0.5 + 0.5`, `t = smoothstep(0.55 − 0.03, 0.55 + 0.03, wrap)`, 빛 = `mix(SHADE, LIGHT, t) + 0.1 × max(N.y, 0)`(위쪽 면 채움). 색 = 정점색(AO 포함) × 빛. `sun_dir = (−0.35, 0.85, 0.45)`(왼쪽 앞 위). 경계가 거의 딱 끊기는 두 단 툰이다.
- 면마다 법선이 하나라 램프를 정점에서 계산해도 결과가 같다. 조각(fragment) 단계는 색을 복사만 해 low에서 싸다.
- **sRGB 처리**: 정점색은 `ArtMeshBuilder`가 sRGB → 선형으로 바꿔 저장한다. Mobile 렌더러는 선형 출력을 sRGB로 바꿔 주지만, Compatibility 렌더러는 unshaded `ALBEDO`를 바꾸지 않고 내보낸다(SM-P200에서 색이 짙게 나오는 것으로 확인). 셰이더가 `OUTPUT_IS_SRGB`일 때 직접 선형 → sRGB로 바꾼다. 새 셰이더도 이 처리를 넣어야 low와 high 색이 같다.
- **블롭 그림자**: `ArtKit.shadow_material()`(unshaded, 알파 블렌드, 깊이 쓰기 없음, 먼저 그림). `add_blob`(둥근 것) / `add_soft_rect`(사각형, 가장자리 페이드). 정적 물체의 그림자는 섬 그림자 메시 하나에 합친다(`build_island`의 `extra_shadows`). 움직이는 물체는 `ArtJuice`가 매 물리 스텝 아래로 광선 하나를 쏴 맞은 면에 그림자를 붙이고, 높을수록 작게 한다. 각도가 바뀌는 장치(빗면)는 바뀔 때만 그림자 메시를 다시 만든다.
- **high 단계 실시간 그림자**: 넣지 않는다. 근거는 [Task 2c 결과 4절](../../../spikes/bench/results/phase1-task2c/README.md#4-high-실시간-그림자-판단).

## 5. 환경

- 배경은 하늘색 단색(`ArtKit.make_environment()`, 환경광 끔). 하늘 셰이더·포그를 쓰지 않는다.
- **떠 있는 잔디 섬**(`ArtKit.build_island(parent, center)`): 윗면이 y = 0인 반지름 11 m 14각 원기둥, 아래로 좁아지는 흙 두 단, 나무 5그루(줄기 + 원뿔 2개), 바위 3개, 꽃 7송이, 뒤쪽 구름 3덩이(구 4개씩). `center` 둘레 약 8 × 6 m는 비워 장치 자리로 둔다. 전부 메시 하나 + 그림자 메시 하나다.
- 구름은 정면 시점에서 보이고 내려다보는 3/4 시점의 위쪽 가장자리에는 걸리지 않는 높이(4.5–6.5 m, 섬 뒤 15–19 m)다.
- 충돌 바닥은 실험이 따로 만든다(빗면 실험은 30 × 12 m 상자, 윗면 y = 0). 섬 메시는 충돌이 없다.

모든 연출은 보이는 것만 움직인다. 지속 시간은 0.5초를 넘기지 않고, 물리 결과를 기다리게 하지 않는다.

## 7. 2D 패널

웹 2D(`src/app/style.css`)의 레이아웃·위젯 구성(카드, 조건 칩, 관찰 타일, 그래프, 설명)은 그대로 두고 색과 모양만 섬 스타일로 바꿨다(`UiTheme`).

- 카드: 흰 바탕, `LINE` 2 단위 테두리, 아래 두께 3, 모서리 18.
- 기본 버튼: 파랑, 진한 파랑 테두리와 아래 두께 5, 모서리 14(장난감 버튼). 보통 버튼: 흰 바탕 + `LINE` 두께.
- 선택: 노랑(칩, 품질 선택, 슬라이더 손잡이). 선택 표시는 파랑이 아니라 노랑이다.
- 단계 번호 배지는 노랑, 목록 카드 아이콘 배지는 파랑 바탕 흰 아이콘.
- 실험 목록 위 머리 그림(`IslandBanner`): 하늘 띠(모서리 18) 안에 구름, 떠 있는 섬, 노란 빗면과 빨간 상자를 다각형 몇 개로 그린다. 그 영역만 칠한다.
- 앱 배경은 clear color `PAPER`다(전체 화면 사각형을 두지 않는다).

## 9. 새 실험 소품 만드는 법

1. `experiments/<실험>/<실험>_props.gd`를 만든다(`InclineProps`를 본뜬다). 물리 바디·충돌 모양은 실험 스크립트가 만들고, props는 메시만 돌려준다.
2. 메시는 `ArtKit.builder()`로 만든다. 부품마다 `add_rounded_box`·`add_cylinder`·`add_sphere`를 부르고 `commit()`한 `ArrayMesh`를 `ArtKit.instance(mesh)`로 감싸 바디의 자식으로 단다. 색은 `ArtPalette`의 장치 색(2절 규칙). 정적인 부품 여러 개는 빌더 하나에 모아 메시 하나로 만든다.
3. 장면을 꾸밀 때 `ArtKit.make_environment()`와 `ArtKit.build_island(실험, center, extra_shadows)`를 부른다. 고정 장치의 그림자는 `extra_shadows`에서 섬 그림자 메시에 더한다.
4. 움직이는 주인공에는 `ArtJuice`를 붙인다: `juice.setup(바디, 바디의 메시, 크기, 바닥 높이)`. 실험의 상태 변화에 맞춰 `pop()`·`stretch()`·`puff()`를 부르고, `juice.landed`를 `impact`(Experiment 신호)에 이어 카메라 반응을 켠다.
5. 카메라(`content/experiments/<id>.json`의 `camera`)는 주인공이 3/4 시점 화면 폭의 1/3 이상을 차지하는 장치 전체가 보이게 `target`·`distance`를 정하고, 시점마다 필요한 `distance`를 따로 준다. 폰 세로(1080×2340)와 태블릿 가로에서 확인한다.
6. 헤드리스 테스트에 "아트는 보이는 것만" 검사를 더한다: 충돌 객체 수, 연출이 바디 메시만 바꾸는지, 연출을 끈 실행과 운동·표시 값이 같은지(`tests/run_tests.gd`의 `_check_art_is_visual_only`).
7. low에서 `apps/lab3d/tools/bench_device.sh`로 60 fps를 확인하고, 드로우콜·정점 수를 8절 예산과 비교한다.
